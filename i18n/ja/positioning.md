# Lollyの比較

このプラットフォームが、より広いクリエイティブツールのランドスケープの中でどこに位置するのか、そして意図的に**関与しない**領域はどこかについて説明します。

> **パイロット版の状況：** Lollyは完成した製品ではなく、クローズドパイロットのプロトタイプであり、そのセキュリティは現在、エンタープライズ規模に備えてSUSEの厳格なインフラストラクチャ強化を受けている最中です。このポジショニングはLollyが*目指している*位置であり、実際にどのようにテストされているかについては[採用とガバナンス](/info/adoption-governance.html#status)ページをご覧ください。

ギャップの形は明らかです。既存のランドスケープの中には、制約ファースト、オフライン対応、低スキルで使え、社内で誰でもアクセスでき、生成的な出力を実現するものは一つもありません。Lollyは現在、独自のオープンキャンバス——直接操作可能な自由キャンバスである**Layout Studio**——を提供していますが、Canvaの列との決定的な違いがあります。その上に配置される色、タイポグラフィ、アセットはブランドのグローバル設定に準拠しており、自由な配置であっても制約ファーストであり続けます。それでもLollyが制約のないデザインスイートでは**ない**という点は変わりません。デザイナーは独自の作品制作には引き続きIllustratorやFigmaを使用するでしょう——そして、その作品がガバナンスの効いた再現可能なアセットになる必要が生じたとき、Layout Studioの[デザインをインポート](/info/design-import.html)機能が、完成したFigma/Illustrator/Penpotファイルを、編集可能でブランドに準拠したボックスとしてキャンバスに取り込みます。

## 向いている用途

![Deck Studio in the split view - the deck's slides listed as blocks on the left, the laid-out deck rendering on the right](/t/url-shot?url=%2F%23%2Ftool%2Fdeck-studio&width=1440&height=900&dpi=192&waitMs=2600&format=svg&dark=1&filename=ov2-deck-studio-output)

Deck Studio は、その天井の高さをよく示す例です。スライドデッキ全体をデータとして宣言し、キャンバス上でライブにレイアウトして、ネイティブに編集可能な PowerPoint として書き出せます。

- 運用可能なクリエイティブアセット（イベントタイル、バッジ、署名、アラートなど）の迅速な生成
- 色、タイポグラフィ、アイコン、画像といった要素がブランドのグローバル設定に準拠し続ける必要がある場合の、オープンキャンバス（Layout Studio）上での自由な配置
- 完成したFigma、Illustrator、InDesign、またはPenpotのデザインを取り込み（Layout Studioの「デザインをインポート」機能）、編集・ガバナンス管理を行い、あらゆるLolly形式で決定論的に再レンダリングできるようにする
- 「3つの項目を入力すれば完成アセットが得られる」という1対多のフロー——`/pro`バッチグリッドでのスプレッドシート/CSVからの一括実行を含む（行を貼り付けまたはインポートし、1行につき1つの完成アセットを生成、zipとしてダウンロード）
- 常時稼働の、定期的なブランド化された出力
- 表現の自由度よりもブランド表現の一元管理が重要となるケース

## 向いていない用途

- オーダーメイドやフラッグシップのヒーローコンテンツ（ビルボード、大型動画など）
- デザイナーを本当に必要とする、唯一無二のキャンペーン制作
- ブランドシステムから完全に逸脱する必要のある発想段階の作業——Lollyのオープンキャンバスは色、タイポグラフィ、アセットを常にブランドのグローバル設定に準拠させており、それこそが狙いです

## 承認するのはファイルではなく、ツール

![The producer's whole job: type the words. Type, colour and spacing were settled when the tool was approved](/t/url-shot?url=%2F%23%2Ftool%2Fwordmark%3Ftext%3DApproved&width=1440&height=900&dpi=192&waitMs=2000&format=svg&dark=1&filename=aud-approve-the-tool)

このランドスケープにある他のツールはどれも*ファイル*を生み出し、そのファイルは後からチェックされなければなりません——Slackのスレッドでブランドマネージャーが確認し、法務が免責文を見て、修正が一巡し、また別のレビューが入ります。Lollyは承認を**一段上流へ**移します。ブランドのルール——正確なカラーコード、ライセンス済みのフォントファイル、塗り足しの余白、余白の取り方——はツールのHTMLとCSSにハードコードされているため、テンプレートはブランドから外れたアセットを*物理的に出力できません*。レイアウトそのものが構造を支えているのです。

そのため、承認するのは成果物ではなく、それを作る**ツール**になります。一度承認すれば、そのツールが以後生み出すすべてのアセットは構造上あらかじめ承認済みです——人が間に入ることも、レビューのサイクルも、どんな物量であっても必要ありません。

これこそが、決定論的なエンジンが実際にもたらすパラダイムシフトです。従来の承認プロセスを速くしたものではなく、プロセスそのものをなくしてしまいます。クリエイティブチームにとっては置き換えではなくガードレールです——ボール（データ、コピー、画像）を投げるのは変わらずあなたで、コードはどの一投も溝に落とさないバンパーレーンなのです。

| 従来のアセット承認 | Lollyのツール承認 |
|---|---|
| 完成したファイルを1つずつチェックする | ツールを一度チェックする |
| 依頼 → デザイナーが制作 → ブランドレビュー → 法務チェック → 修正 → 再レビュー | パラメータを1つ変更 → 完成アセット |
| デザイナー、ブランドマネージャー、法務、依頼者の全員が関わる | 制作担当者が1人で完結 |
| アセット1点につき数日 | アセット1点につき数秒 |
| 10,000点のアセット = 10,000回のレビューサイクル | 10,000点のアセット = ゼロ回（テンプレートはすでに承認済み） |

## Lollyならではの提供価値

![Amsterdam's canal rings and road network drawn edge to edge in the brand's own ink, every stroke placed by the template rather than by hand](/t/url-shot?url=%2F%23%2Ftool%2Fstreet-map%3Fcity%3Damsterdam%26theme%3Dlight%26full&width=1440&height=900&dpi=96&waitMs=3200&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-street-map-poster)

- **文脈の中で安全に発揮される、大胆なデザインの可能性。** ツールは、ハードコードされたガードレールの中で冒険的なデザインのアイデアを表現できます。
- **最終アセットをそのまま返す、ソフトウェア定義のコンテンツ自動化。** 入力 → 完成ファイル。「デザインツールから保存して後処理する」という手間はありません。
- **ツールがツールを組み合わせる。** あるツールが別のツールのレンダリング結果を埋め込み、それを1つの完成アセットの一部として返すことができ、しかもツール間にコードの結合はありません——これは、業界のオープンキャンバス製品やDAMテンプレート化製品のどれも提供していないプリミティブです。
- **ベンダーニュートラリティ。** 機能とコストを完全にコントロール。オープンソースのエンジン。ツールとアセットはgitで管理されたコンテンツであり、SaaSデータベースにロックインされることはありません。

この中で最初の項目こそ、過小評価されがちなものです。ポスター級の都市地図が、道路も水域も真のベクターパスとして描かれ、その入力はドロップダウン1つとカラー欄2つだけ——しかもそれらをブランドの外へ向けることはできません。
